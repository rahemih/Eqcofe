## Authority, security and recovery

Every operation has its own view, exact OpenAPI/controller evidence, permission claims, Step-Up, idempotency scope and If-Match requirement. Mutation input is followed by review; lifecycle dialogs begin with safe cancel. Confirmation is a UX requirement, not a new permission or backend guard. B supplies authentication/Step-Up patterns. Procurement request/PO/return approval preserves creator-versus-approver separation; no invented separation is claimed for other commands.

For ambiguous outcomes, read the existing status route or use manual follow-up. Same-key/unchanged-payload replay is explicit and only for a traced idempotent operation. No automatic retry, new-key retry, optimistic success or silent stale overwrite. Audit markers are shown only if returned; audit writes do not imply a history-read endpoint. Excel direct apply has a possible mutation-then-audit failure boundary; import-job creation is not execution and has no list/status GET.

All four inherited A source-gap sets remain NO_ACTION. D adds explicit source limitations without changing runtime: warehouse scope enforcement is not uniform in cost basis, some reservation commands, landed-cost preview/finalize and unlinked invoices; currency apply lacks current-price/fresh-guard/requester checks and does not prove complete population beyond query cap5001; transfer approval does not reserve stock, and ship has no fresh physical-availability guarantee; return receipt quantity is checked at create, not a claimed fresh approval check. These limitations must be reconciled before executable release; this design gate does not certify runtime readiness.

## Product constraints and field semantics

Retail money and costs remain nonnegative integer Toman. Foreign exchange rate is a positive finite rate-to-Toman measurement; it is not silently retyped as retail money. No Wallet, brown palette, invented assets, paid services, new rules or API changes. FX refresh requires a configured provider and returns an observation/preview; selecting a validated rate never automatically applies price changes. Suspicious/rejected rates cannot be selected as validated. Percentage/fixed money, quantity, dates, warehouse context and stock bucket have distinct visible labels.

List filters are local to loaded records unless explicitly supported by the controller: base-price variant, currency-code rates, inventory variant, reservation status and allocation order-item. Existing collection caps are not pagination or full-population totals. Cost layers and movements are read-only. Supplier invoice details use returned list data because no single GET exists. Excel apply is separate for catalog and pricing; catalog resolves existing objects and does not create products. Real XLSX parser restrictions include macros, external links and formulas; file selection never trusts client-provided security assertions.
